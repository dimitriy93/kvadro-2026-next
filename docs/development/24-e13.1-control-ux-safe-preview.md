## 4. Направление A — диалог подтверждения

Все изменения локальны в `object-control.ui.tsx` (+ стили); сервер не
затронут. Новых зависимостей нет — trap реализован средствами React и
браузера.

### 4.1. Тексты

- Заголовок: `Поставить зону ${zoneNum} под охрану?` /
  `Снять зону ${zoneNum} с охраны?` — номер из фактических данных
  (`partition.num` / `SafePreviewPartition.num`).
- Имя зоны: `zoneLabel(name, num)` — фактическое имя из DTO; пустое или
  отсутствующее имя заменяется нейтральным «Зона N», названия не
  придумываются, `undefined`/`null` в UI не попадают [Код, Тест].
- Содержимое: объект («Объект «{objectName}», зона «{name}»
  (раздел № {num}).»), последствия по операции (arm: «После взятия под
  охрану движение в охраняемых зонах вызовет тревогу.»; disarm: «Объект
  останется без охранной защиты этого раздела.»), предупреждение режима.
- Рабочий режим: «Рабочий режим: подтверждение отправит команду в систему
  мониторинга GEORITM.»; демо-режим: точный текст «Демонстрационный
  режим. Реальная команда не отправляется. Управление охраной пока
  недоступно».
- Кнопки: «Отмена», «Подтвердить». Тексты соответствуют операции —
  заголовок, последствия и команда формируются из одного снимка цели
  (раздел 4.3), перепутать arm/disarm невозможно [Код, Тест, Браузер].

### 4.2. Accessibility

- Перенос фокуса: при открытии `panelRef.current?.focus()` (панель
  `tabIndex={-1}`) [Браузер: activeElement = panel].
- Возврат фокуса: cleanup эффекта вызывает `restoreRef.current?.focus()`
  — фокус возвращается на кнопку раздела, открывшую диалог [Браузер].
- Focus trap: keydown на оверлее, `FOCUSABLE_SELECTOR` по панели, цикл
  Tab/Shift+Tab, включая граничные случаи «фокус на самой панели»
  (дефект 10 найден проверкой Shift+Tab сразу после открытия и
  исправлен) [Браузер].
- Escape: закрывает диалог (семантика «Отмена»); во время операции —
  игнорируется [Браузер].
- Клик по оверлею: закрывает только при `event.target ===
  event.currentTarget`; клик внутри содержимого не закрывает [Браузер:
  реальный клик по оверлею закрыл; клик по заголовку — нет].
- `role="dialog"`, `aria-modal="true"`, `aria-labelledby=
  "obj-control-modal-title"`, `aria-describedby=
  "obj-control-modal-description"` — доступное имя из заголовка [Браузер].
- Видимый focus indicator: `:focus-visible` outline для кнопок секции и
  диалога (стили) [Браузер: зеленый outline на кнопке после возврата фокуса].
- Блокировка повторного подтверждения: `disabled={target.demo || busy}`;
  во время операции заблокированы «Подтвердить» и «Отмена», Escape и
  оверлей игнорируются, диалог показывает «Выполняется…» (`role="status"`,
  `aria-live="polite"`) — закрытие, создающее неоднозначность результата,
  исключено [Код].
- Статус операции также продублирован баннером секции (прежнее поведение
  E12 сохранено).

### 4.3. Фиксация цели подтверждения (сценарий 5, несколько разделов)

Цель — снимок примитивов `{action, zoneNum, zoneName, demo}`,
зафиксированный в момент нажатия кнопки конкретного раздела (ранее —
снимок `{action, partition}`). Диалог рендерится только из снимка и не
пересчитывается из обновлённых списков: изменение состояния React не
может переключить операцию на соседнюю зону [Код, Браузер: раздел № 1 —
постановка, раздел № 2 — снятие, значения корректны].

## 5. Направление B — Safe Preview

### 5.1. Принцип

Safe Preview — **исключительно UI-режим**, не альтернативный путь команд:

- при `enabled: false` секция рендерится с демонстрационным баннером
  (точный текст постановки), фактическим состоянием разделов и
  демонстрационными кнопками [Код, Браузер];
- данные состояния — **только уже загруженные DTO зон**
  (`ObjectZoneSection[]`, загружаются страницей объекта независимо от
  gate): `deriveSafePreviewPartitions` (`object-control.shared.ts`,
  серверный модуль без `'use client'`) выводит `{num, name, guarded}` —
  `'armed'` → под охраной, `'disarmed'` → снят, тревога/неисправность/
  прочее → `null` («Состояние неизвестно»). Ни одного нового запроса к
  GEORITM или источнику; фиктивные состояния не создаются [Код, Тест];
- capability при выключенном gate не вычисляется и не имитируется:
  `SafePreviewPartition` сознательно не содержит `arm`/`disarm` [Код];
- диалог: корректное действие/объект/раздел + точное демо-уведомление;
  «Подтвердить» **заблокирован** (`disabled`), обработчик — `() =>
  undefined` (даже при снятии disabled извне API недостижим); «Отмена»
  закрывает; закрытие Escape/овереем возвращает к карточке [Браузер];
- разделы с `guarded === null` показывают «Состояние неизвестно» и **не
  имеют кнопки** — не предлагается операция, безопасность которой нельзя
  определить (сценарий 3) [Код, Браузер: раздел 3 «Подсобное помещение»].

### 5.2. Запреты соблюдены [Код]

- `GEORITM_CONTROL_ENABLED` не включался; обхода gate нет — Safe Preview
  ветвится по `initial.enabled === false` (значение, которое сервер
  возвращает только при выключенном gate).
- Реальный POST через control route невозможен: маршрут не менялся
  (403 `gate-disabled` при выключенном gate подтверждён тестами E12.23 и
  статической проверкой смоука); клиентский Safe Preview не содержит
  вызова control-маршрута (ветка не имеет `fetch`, см. 8).
- Отдельного API-эндпоинта-имитатора нет; фальшивых сообщений
  «Команда выполнена» нет; IMEI/`canArm`/права/состояния не подставляются;
  capability resolver не менялся; серверные проверки не ослаблялись.

## 6. Как исключена отправка реальных команд

1. **Клиент [Код, Тест]:** компонент содержит ровно два `fetch`-вызова —
   GET-опрос `/api/cabinet/objects/{id}/partitions` (только после
   'unknown'-результата рабочего режима) и POST `/control` (только
   рабочий режим, только через `runOperation`, достижимый исключительно
   из недемо-диалога). Демо-ветка диалога вызывает `() => undefined`.
   Проверено статическим смоуком (пункт 8) и в браузере.
2. **Браузер [Браузер]:** все сценарии (открытие обоих диалогов, отмена,
   Escape, оверлей, trap, повторные нажатия, 375px, обе темы) выполнены
   с мониторингом `performance.getEntriesByType('resource')` — **ноль
   запросов к `/api/`** за всю серию.
3. **Сервер [Тест]:** маршрут control неизменён; при выключенном gate —
   403 `gate-disabled` + `controlDisabled: true` и ноль вызовов модуля
   управления (смоуки E12.14/E12.23 пройдены повторно). Никакой новый
   эндпоинт не создавался.
4. **Gate/окружение:** переменная отсутствует, `.env.local` не изменялся;
   в отчётный период write-методы GEORITM не вызывались ни разу.

## 11. Оставшиеся ограничения

1. **Gate остаётся выключенным.** Safe Preview не приближает допуск
   реального управления: блокеры E13 (ответы поставщика P1–P4, аудит-журнал
   F8, не-администраторская учётка, контрольная серия команд) без изменений.
2. **Состояние Safe Preview — из obj-card/** (метод зон страницы), а не из
   `objects/state/` (метод рабочего режима): при выключенном gate это
   единственные уже загруженные данные; возможные расхождения не
   влияют на безопасность — команды в этом режиме не существует.
3. **Демо-подтверждение заблокировано** (вариант «disabled» из
   постановки); вариант «явно обозначенное демонстрационное действие»
   не реализовывался — заблокированная кнопка + точное уведомление
   однозначно исключают ожидание реального результата.
4. **Компонентных тестов в проекте нет** — поведенческое покрытие
   выполнено разовой браузерной проверкой (результаты в 8.2); при
   появлении тестовой инфраструктуры сценарии 8.2 рекомендуется
   перенести в автоматизированные e2e.
5. **Скриншот светлой темы** не получен (ограничение инструмента захвата
   сессии); корректность проверена computed styles (раздел 7). Тёмная
   тема проверена скриншотами.
6. **Реальный рабочий режим (gate on)** в браузере не прогонялся —
   включение gate запрещено постановкой; рабочий режим не менялся
   семантически (тексты диалога и блокировки закрытия расширены),
   серверные смоуки E12/E13 проходят, маршруту и resolver изменения
   не требуются.
