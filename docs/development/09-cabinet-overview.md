# 09. Личный кабинет: обзор

Кабинет — отдельная подсистема сайта: клиент видит состояние своих объектов мониторинга. **Текущее состояние — прототип на демонстрационных данных**; реальный источник GEORITM не подключён (см. [12-georitm-integration.md](./12-georitm-integration.md)).

## Маршруты и страницы

| URL | Назначение | Данные отображаются | Компонент UI |
|---|---|---|---|
| `/cabinet/login` | Вход | Форма логин/пароль; в dev — подсказки демо-учётных записей | `app/(cabinet-login)/cabinet/login/ui/login.ui.tsx` (клиентский) |
| `/cabinet` | Список объектов | Карточки: название, адрес, id, статусы (охрана/пожар/связь), «Обновлено» | `app/(cabinet)/cabinet/ui/objects-overview.ui.tsx` |
| `/cabinet/objects/[id]` | Карточка объекта | Общая информация, состояние систем, список зон с состояниями | `app/(cabinet)/cabinet/objects/[id]/ui/object-state.ui.tsx` |
| `/cabinet/objects/[id]/events` | Журнал событий | Список записей (новые сверху), фильтр по типу через `?type=` | `.../ui/object-events.ui.tsx` |
| `/cabinet/objects/[id]/map` | Карта объекта | Декоративный SVG-план, заглушка | `.../ui/object-map.ui.tsx` |

Оболочка — `app/(cabinet)/cabinet/ui/account-shell.ui.tsx` (шапка с логотипом, «Объекты», именем пользователя, «Выйти»; футер «демонстрационный прототип»). Вкладки объекта — `.../objects/[id]/ui/object-page-header.ui.tsx`.

Отображение статусов: `app/(cabinet)/cabinet/ui/state-meta.ts` — словари `SECURITY_STATES` / `FIRE_STATES` / `CONNECTION_STATES` (подпись + визуальный тон), индикаторы — `object-state-badge.ui.tsx`. Даты — `formatDateTime` (`ui/format.ts`), таймзона Europe/Moscow.

## Возможности пользователя (фактические)

- войти по логину и паролю;
- увидеть **только свои** объекты;
- открыть карточку объекта: состояния охранной/пожарной сигнализации, связи, зоны;
- просмотреть журнал событий с серверным фильтром по типу (`?type=security_armed` и т. д., валидация через `isDemoEventType`);
- выйти.

Чего **нет**: управления (постановка/снятие с охраны), уведомлений, карты с реальной геометрией, регистрации, смены пароля.

## Демо-данные

Источник — `lib/account/demo-data.ts` и `lib/account/demo-events.ts` (только серверный код! модуль содержит фиктивные пароли и импортировать его в клиентские компоненты запрещено).

**Учётные записи** (`DEMO_USERS`):

| Логин | id | Объекты |
|---|---|---|
| `belochka` | `demo-user-belochka` | Магазин «Белочка» |
| `romashka` | `demo-user-romashka` | Магазин «Ромашка» |

Пароли демонстрационные и заданы в том же файле; они предназначены **исключительно для локальной разработки**: в production демо-вход отключён серверно (`isDemoLoginEnabled()` возвращает `false` при `NODE_ENV === 'production'`), и подсказки с паролями на странице входа не передаются. Подтверждено тестами: production-вход по демо-данным отвечает 503.

**Объекты** (`DEMO_OBJECTS`): Магазин «Белочка», Магазин «Ромашка», и Склад «Западный» — **специально не привязан ни к одному пользователю**, чтобы проверять изоляцию доступа (чужой объект → 404, неотличимый от несуществующего).

**Зоны** (`DEMO_ZONES`): 4–5 зон на объект, у каждой система (`security`/`fire`) и типизированное состояние (дискриминированное объединение в `contracts.ts` не позволяет смешать наборы состояний охраны и пожара).

**События** (`DEMO_EVENTS` в `demo-events.ts`): по 4–8 записей на объект, типы из `DEMO_EVENT_TYPES`, сортировка «новые сверху».

Проверка изоляции вручную: войти как `belochka` → открыть `/cabinet/objects/demo-object-sklad-zapadnyy` → должна быть кабинетная 404 («Объект не найден»), идентичная 404 для несуществующего id.

## Как запустить локально

```bash
npm install
npm run dev
# http://localhost:3000/cabinet → редирект на /cabinet/login
# на форме входа — блок «Тестовые учётные записи» с кнопками автозаполнения
```

Требование: переменная `ACCOUNT_SESSION_SECRET` в dev не обязательна (есть dev-fallback), в production — обязательна (см. [10-cabinet-authentication.md](./10-cabinet-authentication.md)).

## Ограничения прототипа

- Все данные — константы в коде; никакой persistence.
- Нет управления оборудованием (read-only по дизайну).
- «Обновлено» — фиксированные даты из демо-данных.
- Модель сессии — stateless HMAC-токен без отзыва и rate limiting; до production-использования требуется переход на серверное хранилище сессий (план — этап 2 интеграции GEORITM).
- Карта — заглушка без картосервисов.
