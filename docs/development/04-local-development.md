# 04. Локальная разработка

## Требования к окружению

| Требование | Версия | Примечание |
|---|---|---|
| Node.js | 20+ (разработка ведётся на v24) | API-роуты используют `node:fs` и `node:crypto` |
| npm | 10+ (использовался 11.x) | есть `package-lock.json` |
| ОС | Windows / Linux | проект разрабатывается на Windows (Git Bash), деплой — Linux (Amvera) |

## Установка и запуск

```bash
# 1. Установить зависимости
npm install

# 2. Запустить dev-сервер
npm run dev
# → Ready on http://localhost:3000

# 3. Открыть в браузере
# Публичная часть:  http://localhost:3000/
# Кабинет:          http://localhost:3000/cabinet
```

Первое открытие каждой страницы компилируется «на лету» — первая загрузка может занять от нескольких секунд до минуты (особенно на медленной ФС: Next выведет предупреждение «Slow filesystem detected»). Последующие переходы быстрые.

## Команды `package.json`

```bash
npm run dev     # dev-сервер (Turbopack), http://localhost:3000
npm run build   # production-сборка в .next/
npm run start   # запуск production-сборки (сначала нужен build)
```

Проверка типов (отдельного скрипта нет, линтера нет):

```bash
npx tsc --noEmit
```

## Переменные окружения

Задаются в **`.env.local`** в корне проекта (файл в `.gitignore`, в репозиторий не попадает). Список необходимых переменных:

```bash
# Telegram-бот для заявок с сайта (значения — placeholder, реальные в .env.local на хостинге)
TELEGRAM_BOT_TOKEN=<токен бота>
TELEGRAM_CHAT_ID=<id чата>

# Cloudflare Turnstile (антибот для форм)
NEXT_PUBLIC_TURNSTILE_SITE_KEY=<site key>
TURNSTILE_SECRET_KEY=<secret key>

# Секрет сессии личного кабинета (HMAC-подпись токена)
# В dev отсутствует безопасный fallback; в production БЕЗ неё кабинет не работает (fail-closed)
ACCOUNT_SESSION_SECRET=<длинная случайная строка>
```

- `NEXT_PUBLIC_*`-переменные инлайнятся в клиентский бандл на этапе сборки — их изменение требует перезапуска dev-сервера / пересборки.
- Для локальной разработки `ACCOUNT_SESSION_SECRET` можно не задавать: `lib/account/session.ts` использует фиксированный dev-секрет (только при `NODE_ENV !== 'production'`).

## Dev-режим vs production — что меняется

| Аспект | dev | production |
|---|---|---|
| Демо-вход в кабинет | Включён: на `/cabinet/login` видны тестовые учётные записи | **Отключён серверно**: `POST /api/cabinet/login` отвечает 503 (`isDemoLoginEnabled()`, `lib/account/session.ts`) |
| Подсказки паролей на форме входа | Показываются | Не передаются (`app/(cabinet-login)/cabinet/login/page.tsx` проверяет `NODE_ENV`) |
| Секрет сессии | Fallback-константа | Только `ACCOUNT_SESSION_SECRET`; без неё токены не выпускаются и не проверяются |
| Скрипт очистки мёртвых Service Worker | Выполняется на localhost | Полностью исключён из сборки (`app/layout.tsx`) |
| Ошибки в консоли браузера | Подробные + оверлей Next.js Dev Tools | Минимальные |

## Остановка и перезапуск

- Остановка: `Ctrl+C` в терминале с `npm run dev`.
- **Запускать два dev-сервера на одном каталоге нельзя**: второй процесс упадёт («Another next dev server is already running») или займёт другой порт. Если порт 3000 занят зависшим процессом:

```bash
# Windows: найти и убить процесс на порту 3000
netstat -ano | findstr :3000
taskkill /PID <pid> /F
```

## Типичные проблемы запуска

| Симптом | Причина | Что делать |
|---|---|---|
| «Port 3000 is in use» / «Another next dev server is already running» | Остался старый процесс dev-сервера | Убить процесс по PID (см. выше) |
| Первая загрузка страницы 30–60 с | Компиляция по требованию + медленная ФС | Норма; просто подождать |
| После правки env-переменной ничего не изменилось | `NEXT_PUBLIC_*` инлайнится при сборке | Перезапустить dev-сервер |
| Кабинет «завис» на старых данных / кнопки не работают | Зомби-Service Worker в браузере | См. [14-troubleshooting.md](./14-troubleshooting.md) |
| Ошибки типов в `.next/types/...` при `tsc --noEmit` | Устаревшие сгенерированные валидаторы маршрутов | Перезапустить dev-сервер или выполнить `npm run build` (перегенерируют) |

## Полезно знать

- **`.env.local` содержит реальные секреты** (токен Telegram-бота) — не коммитить, не копировать в чаты/доки.
- Логи dev-сервера пишутся в терминал; файлы `dev.out` / `dev.err` в корне — ручные артефакты прошлых запусков (в `.gitignore` не добавлены).
- Кэш Turbopack хранится в `.next/dev/`; при странном поведении сборки помогает остановка сервера и удаление `.next/`.
